## 2. 怎麼用

1. 到「報表」，展開「本日交易明細」。
2. 找到要處理的那一筆，按右下角「作廢」。
3. 確認框會列出作廢後會發生什麼，以及**要退給客人多少錢**。
4. 原因可選「結錯帳」「客人退款」，也可以自己打字，或留空。
5. 按「確定作廢」。

結錯帳的話：作廢錯的那筆，再到「銷售」重新結一筆正確的。

---

## 3. 作廢會做什麼

| 項目 | 行為 |
|---|---|
| 交易紀錄 | **保留**，加上「已作廢」標記、作廢時間、原因。不會真的刪掉 |
| 報表頁 | 本日營收、所有管道總計不再計入；明細卡片顯示刪除線＋「已作廢」；日期列多一個「作廢 N 筆」 |
| 庫存 | 自動加回去（單賣、套組本身、套組內容物都加回，算法跟結帳扣庫存一樣） |
| 預購取件 | 預購單改回「未取件」，可以重新取件 |
| Excel 流水帳 | 保留一列，類型＝「作廢」，數量和金額都是 0；備註寫原本的金額、品項、原因 |
| Excel SUMMARY | 所有數字都扣掉作廢的；最下面多一塊「作廢紀錄」，列出每一筆原金額 |
| Excel 類別頁 | 不放作廢的交易 |
| 舊格式 CSV | 不計入作廢的交易 |
| 封存場次 | 不顯示「作廢」按鈕（封存是唯讀） |

## 5. 改動的檔案

| 檔案 | 改了什麼 |
|---|---|
| `src/lib/voidTx.js`（新） | 作廢判斷、要加回的庫存、原因整理 |
| `src/db.js` | 新增 `voidTransaction()`：加回庫存、標記作廢、預購改回未取件，全部包在同一個 transaction，失敗就整筆回滾；備份驗證多檢查 `voided`、`voidReason` |
| `src/lib/reporting.js` | 本日營收、兩個 CSV 排除作廢；營收摘要多回傳 `voidedCount` |
| `src/lib/reportModel.js` | 流水帳保留作廢列（數量金額 0）、合計只算有效交易；SUMMARY 加作廢紀錄 |
| `src/components/TxDetailList.jsx` | 作廢按鈕、確認面板、作廢樣式 |
| `src/pages/Reports.jsx` | 接上作廢、作廢後重新載入、封存場次唯讀 |
| `src/i18n/strings.js` | 作廢相關文字 |
| `src/lib/__tests__/voidTx.test.js`（新） | 17 個測試 |

交易資料多三個**選填**欄位：`voided`（true）、`voidedAt`（時間）、`voidReason`（文字）。沒有這些欄位的舊交易一律當作有效，所以不用升級資料庫。

## 6. 已知限制

### ISSUE-1　預購 B 的「同批加購」要分開作廢
預購 B 取件時如果有加購，會存成兩筆交易（尾款一筆、加購一筆）。作廢尾款那筆不會自動作廢加購那筆，確認框裡有提醒。

### ISSUE-2　不能「取消作廢」
作廢後不能還原。按錯的話，請重新結一筆一樣的。所以確認要按兩次。

### ISSUE-3　部分退款
目前只能整筆作廢。只退一部分的話：整筆作廢，再重新結一筆客人留下的商品。

### ISSUE-4　退錢要自己處理
App 只改帳，不會動到實際的錢。現金請當場退；LINE Pay 等電子支付請到各自的 App 退款。
